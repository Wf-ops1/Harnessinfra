## Contrato técnico congelado

1. `OpenAIAdapter` executará HTTP real contra a Responses API, com base URL configurável, chave apenas
   em memória e `store=false`; nenhuma resposta poderá ser produzida sem resposta HTTP válida.
2. `LocalAdapter` executará HTTP real contra endpoint configurável compatível com OpenAI Chat
   Completions; autenticação será opcional e nenhum fallback sintético será permitido.
3. O transporte será implementado sobre `httpx`, dependência já bloqueada. Timeout, quantidade de
   retries e backoff serão configuráveis; nenhum SDK ou lockfile novo será introduzido.
4. Cancelamento será cooperativo e observável antes/durante a chamada, durante backoff e antes de
   aceitar o resultado. Cancelar fecha o cliente HTTP da tentativa e lança erro tipado, sem retry.
5. Somente `timeout`, `rate_limit` e `unavailable` serão transitórios. `auth`, `invalid_request`,
   resposta inválida, cancelamento e provider não implementado nunca serão repetidos.
6. Erros públicos terão categorias estáveis `auth`, `rate_limit`, `timeout`, `invalid_request` e
   `unavailable`; payloads/mensagens serão limitados e redigidos com o segredo dinâmico antes da exceção.
7. `LLMResponse` carregará `provider`, modelo retornado pelo servidor, request/response ID disponível,
   usage real e conteúdo real. Ausência ou inconsistência de campos obrigatórios falhará fechado.
8. Tool calls serão objetos estritos e imutáveis com ID, nome e argumentos JSON tipados. F3.1 apenas
   traduz a resposta; não autoriza, executa, persiste nem repete tool calls — isso pertence à F3.3.
9. Structured output enviará JSON Schema estrito quando suportado, fará parse do conteúdo e validará
   localmente com `jsonschema`; conteúdo inválido nunca será retornado como sucesso.
10. `AnthropicAdapter` permanecerá sem integração nesta tarefa e lançará
    `ProviderNotImplementedError` em todas as operações, em vez de resposta fabricada.
11. `ProviderRegistry` e `ModelRouter` manterão a superfície compatível. Roteamento por configuração,
    allowlist efetiva, fallback entre providers, budget e persistência em node event são F3.2.
12. O teste live remoto será explicitamente condicionado a `RUN_LIVE_MODEL_INTEGRATION=1`,
    `OPENAI_API_KEY` e modelo configurado; sem opt-in/segredo, haverá um único skip documentado e zero custo.

## Rollback

### Gatilhos

- qualquer operação retornar conteúdo, usage, modelo, tool call ou request ID fabricado;
- erro não transitório for repetido ou cancelamento causar nova tentativa;
- segredo aparecer em exceção, saída de teste, log, dossiê ou arquivo;
- structured output ou tool arguments inválidos forem aceitos;
- teste live executar sem todos os opt-ins ou tocar provider não autorizado;
- algum critério focado, regressão, qualidade, lock ou escopo falhar;
- implementação exigir arquivo, dependência, efeito ou critério fora do congelado.

### Procedimento não destrutivo

Parar e preservar saídas. Antes de commit de implementação, inverter somente os hunks F3.1 com
`apply_patch`; depois de commit, usar `git revert` apenas nos commits exclusivos desta branch. Para
interromper uma chamada em andamento, cancelar pelo token e fechar somente o cliente daquela tentativa.
Nunca usar `git reset --hard`, `git clean`, descarte amplo, force-push ou sobrescrita de trabalho.

### Verificação pós-rollback

Confirmar `git status --short`, `git diff --check`, HEAD/checkpoint e zero diff de produto contra
`checkpoint/f3.1-ready`; repetir `tests/unit/test_models.py`, suíte integral, mypy, Ruff, compileall e
`uv lock --check`. Se a branch já tiver PR/merge, usar revert auditável sem alterar evidência histórica.
